## 1. Постановка задачи

Требуется численно вычислить определённый интеграл

$$
I = \int_a^b f(x)\,dx
$$

Разобьём отрезок $[a,b]$ на $N$ равных частей:

$$
h = \frac{b-a}{N}
$$

В качестве численного метода используется **метод средних прямоугольников**.

Для каждого отрезка вычисляется значение функции в его середине:

$$
x_i = a + \left(i + \frac{1}{2}\right)h
$$

Приближённое значение интеграла:

$$
I_N = h\sum_{i=0}^{N-1} f(x_i)
$$

В работе рекомендуется использовать функцию

$$
f(x)=\sin(x)
$$

на отрезке

$$
[0,\pi]
$$

Для неё точное значение интеграла известно:

$$
\int_0^\pi \sin(x)\,dx = 2
$$

Значение $2$ используется для проверки корректности результата.

## 2. Базовая последовательная реализация

Ниже приведён **базовый последовательный пример**. Он нужен как эталон для проверки результата и времени выполнения.

```java
public class Main {

    static double integrate(double a, double b, long n) {
        double h = (b - a) / n;
        double sum = 0.0;

        for (long i = 0; i < n; i++) {
            double x = a + (i + 0.5) * h;
            sum += Math.sin(x);
        }

        return sum * h;
    }

    public static void main(String[] args) {
        double a = 0.0;
        double b = Math.PI;
        long n = 100_000_000L;

        long start = System.nanoTime();

        double result = integrate(a, b, n);

        long end = System.nanoTime();

        double time = (end - start) / 1_000_000_000.0;

        System.out.println("Result = " + result);
        System.out.println("Time   = " + time + " s");
    }
}
```

### Что делает программа

Переменная `n` задаёт количество элементарных участков разбиения.

Чем больше `n`, тем:

- больше вычислений выполняется;
- потенциально точнее результат;
- дольше выполняется программа.

Для исследования производительности значение `n` должно быть достаточно большим, чтобы вычисление занимало заметное время.

## 4. Задание 2. Параллельная реализация

Разделите диапазон вычислений между несколькими потоками.

Например, для четырёх потоков:

```text
0 --------------------------------------------------------- N

|--------------|--------------|--------------|--------------|
   Thread 0       Thread 1       Thread 2       Thread 3
```

Каждый поток должен самостоятельно вычислить часть суммы.

Желаемая схема:

```text
Thread 0 -> localSum0
Thread 1 -> localSum1
Thread 2 -> localSum2
Thread 3 -> localSum3

localSum0
    +
localSum1
    +
localSum2
    +
localSum3
    =
result
```

### Важное требование

Не следует синхронизировать каждое сложение в общей переменной.

Нежелательный вариант:

```text
for (...)
    synchronized (...)
        totalSum += ...
```

В таком случае потоки начинают постоянно конкурировать за один и тот же ресурс, и значительная часть преимуществ параллельного выполнения теряется.

Используйте локальную сумму каждого потока, а затем объедините результаты.

## 7. Ускорение

Пусть:

- $T_1$ — время выполнения последовательной версии;
- $T_p$ — время выполнения версии с $p$ потоками.

Тогда ускорение:

$$
S_p = \frac{T_1}{T_p}
$$

Например, если:

```text
T₁ = 10 секунд
T₄ = 3 секунды
```

то

$$
S_4 = \frac{10}{3} \approx 3.33
$$

Идеальное ускорение при четырёх потоках составило бы $4$.

---

## 8. Эффективность

Эффективность показывает, насколько полно используются потоки:

$$
E_p = \frac{S_p}{p}
$$

В процентах:

$$
E_p = \frac{S_p}{p}\cdot100\%
$$

Например, при ускорении $3.33$ на четырёх потоках:

$$
E_4 \approx 83.3\%
$$

## 9. Проверка корректности

Параллельная программа должна вычислять то же математическое значение, что и последовательная.

Для выбранной функции точное значение равно:

```text
2.0
```

Однако результат программы не обязан быть **бит-в-бит одинаковым**.

Причина заключается в особенностях представления вещественных чисел `double` и порядке операций сложения.

Например,

$$
(a+b)+c
$$

и

$$
a+(b+c)
$$

могут дать немного разные результаты.

Поэтому проверяйте нестрогое равенство:

```java
double expected = 2.0;
double epsilon = 1e-10;

if (Math.abs(result - expected) < epsilon) {
    System.out.println("Correct");
}
```

Требуемая точность должна быть одинаковой для всех вариантов программы.

## 10. Важное условие эксперимента

При изменении количества потоков **объём работы не должен меняться**.

То есть при сравнении:

```text
1 поток
2 потока
4 потока
8 потоков
```

должно использоваться одно и то же значение `N`.

Нельзя сравнивать варианты, в которых один использует `10^7` итераций, а другой `10^8`.

Иначе измерение не позволяет сделать вывод об эффективности многопоточности.

## 15. Рекомендации по реализации

Для первого варианта параллельной реализации можно использовать обычный класс `Thread`.

То есть необходимо:

1. создать нужное количество потоков;
2. распределить между ними диапазоны вычислений;
3. выполнить вычисления независимо;
4. дождаться завершения потоков с помощью `join()`;
5. объединить частичные результаты.

Рекомендуется:

- не использовать глобальную синхронизируемую сумму на каждой итерации;
- хранить промежуточную сумму отдельно для каждого потока;
- после завершения потоков объединить частичные результаты;
- не менять объём вычислений при изменении количества потоков.

Использование `ExecutorService` допускается как дополнительный вариант после реализации решения на `Thread`.
